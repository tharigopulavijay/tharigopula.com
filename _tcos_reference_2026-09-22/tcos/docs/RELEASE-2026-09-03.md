## Production rule

Do not run `wrangler d1 migrations apply tcos-db --remote` on the original
database. Its `d1_migrations` ledger is empty although schema 001–010 already
exists, so Wrangler currently proposes replaying all 23 files.

The production release must:

1. Take a fresh full export immediately before maintenance.
2. Apply 011–015 individually by filename.
3. Apply the compatibility migration 016 from the nested folder.
4. Apply 017–024 individually by filename.
5. Run foreign-key, table and clinical row-count checks.
6. Deploy the Worker, then Pages.
7. Exercise sign-in, patient read, prescription read, billing, upload and AI
   draft review before ending maintenance.
8. Baseline `d1_migrations` only after the deployed schema is verified, so all
   future releases return to ordinary Wrangler-managed migrations.

Never copy a database export into GitHub, a support ticket, or chat.
